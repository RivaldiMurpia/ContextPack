ContextPack — App Map

A standalone snapshot of the working proof of concept. Offline-safe. Generated after the final Slice 9 live verification.

What This App Does

ContextPack turns messy project notes into a structured handoff with seven fixed sections (Goal, Current State, Key Decisions, Constraints, Open Questions, Missing Context, Next Actions). The user brings their own OpenAI-compatible endpoint, API key, and exact model ID. The browser sends a same-origin request to a small Vercel serverless function, which calls the provider with strict JSON Schema structured output, validates the result with Zod, and returns only the validated pack. No persistence: refresh clears everything.

How One Generate Flows

3-Stop Route

  1. Entry — validation and request
    src/main.js → search handleGenerate. Validates endpoint URL, key presence, model selection, and context length; sends { baseURL, apiKey, model, reasoningEffort, context } to same-origin /api/generate.
  2. Core — structured generation
    api/generate.js → search chat.completions.create. Uses caller baseURL + key + exact model, strict JSON Schema from api/schema.js, system prompt from api/prompt.js. Adds reasoning_effort only when Thinking is not Auto. Validates with ContextPackSchema.safeParse.
  3. Result — render and copy
    src/main.js → search renderResult; src/copy.js → search buildMarkdown. Renders all seven sections together with semantic card styles from src/styles.css; copy buttons build Markdown client-side.

To Change This, Start Here

  • Prompt behavior → api/prompt.js (SYSTEM_PROMPT). Grounding and classification rules live here; no client changes needed.
  • Output shape → api/schema.js (ContextPackSchema + RESPONSE_JSON_SCHEMA). Both must stay in sync.
  • Validation messages → src/main.js (validateInput). Client mirrors server limits.
  • Copy format → src/copy.js (buildMarkdown, buildAiMarkdown).
  • Demo input → src/example.js (DEMO_INPUT).
  • Styling → src/styles.css (CSS variables at top for palette).

A Practice to Reuse

Decision: the build wrote a strict JSON Schema (api/schema.js → RESPONSE_JSON_SCHEMA) and paired it with an independent Zod validator before any client rendering existed.

Evidence: when the demo showed the model linking unrelated notes ("John checking Supabase pricing"), the fix was a prompt-only change under Source Grounding — no client or server architecture touched.

Reuse: on the next project, specify the machine-checkable output contract first (schema + validator), then build the UI. Interpretation bugs stay isolated in the prompt layer.
